## Part 1. The five open questions, answered

Each question from `docs/2.problem.md` section 8 is answered with evidence. Details and sources follow in Parts 2 to 6.

### Q1. Which language pairs and sizes does TranslatePsy-AfriSLM ship, and are English and Swahili included?

**Answer. Yes, both confirmed.** AfriSLM ships in three sizes, **0.8B, 2B, and 4B**, each a full-parameter supervised fine-tune of the matching Qwen3.5 base. It covers English plus **19 African languages**, and **Swahili (code sw) is one of them**. The full list is English, Afrikaans, Amharic, Hausa, Igbo, Kinyarwanda, Lingala, Luganda, Malagasy, Nyanja, Oromo, Shona, Somali, Sesotho, Swahili, Setswana, Wolof, Xhosa, Yoruba, and Zulu. Every pair is bidirectional, so English to Swahili and Swahili to English both work. Quantized builds exist per size in **GGUF Q8_0 and Q4_K_M**, which is what we run on device.

**So what.** The core translation pair for our demo is officially supported. We are not bending a model outside its training. See Part 2.

### Q2. Does QVAC transcription handle Swahili speech and Kenyan-accented English?

**Answer. Swahili yes, via Whisper. Kenyan-accented English needs testing.** QVAC transcription offers two engines. The first, **qvac-fabric-speech.cpp**, runs whisper.cpp models (`.bin` files), and upstream whisper.cpp lists **Swahili (code sw)** among its supported languages, so Whisper tiny or base covers both English and Swahili speech. The second engine, NVIDIA Parakeet, has a multilingual variant but is heavier. Critically, QVAC's own lightweight **TranscribePsy-250M-EU-sub is European-only (8 languages)** and must NOT be used for Swahili. So the voice-input plan is **Whisper, not QVAC's own small model**. Whether Whisper handles Kenyan-accented English well is untested and is an open demo risk, so we test on a real voice early and keep a typed-input fallback.

**So what.** Voice input in both languages is feasible through Whisper. We validate accent robustness on a physical device before demo day and always keep typing as a fallback. See Part 3.

### Q3. End-to-end latency and memory on the target device, and which device do we demo on?

**Answer. Reference points are in hand. The exact number is ours to measure.** QVAC's published on-device figures for its small transcription model are a useful floor. On a phone, TranscribePsy-250M-EU-sub runs at **real-time factor 0.052, about 1021 ms latency, 252 ms cold start, 534 MiB peak memory, 305 MB size**. That is fast and light, but it is European-only, so our Whisper model will be somewhat heavier. For translation, the AfriNano line (Bergamot, 17M to 43M parameters) is documented to **cut peak RAM about 3.53x against NLLB and to be about 56.7x smaller**, which shows the floor for translation memory on low-end hardware. Our real number depends on the AfriSLM size we pick and the machine, so we measure the full speak-to-speak pipeline on the target device and report it honestly.

**Demo device decision.** Demo on the **Apple Silicon Mac** (arm64, 16 GB RAM, macOS 27). QVAC fully supports macOS 14+ on arm64 with Metal, and the builder has no physical phone. QVAC does not run in emulators, so a phone we cannot test would be a liability. The Mac comfortably runs the 0.8B GGUF model plus Whisper tiny. We record the fully-offline demo on the Mac and note its chip, OS, and RAM in the submission. The Android phone is documented as the deployment target, not the demo device.

**So what.** We have credible latency and memory floors from QVAC's own benchmarks, and a concrete plan to measure our real pipeline on the demo Mac. See Parts 3 and 5.

### Q4. What is the smallest model that still demos well?

**Answer. AfriSLM-0.8B in Q4_K_M for the main demo, with AfriNano as a low-end option.** The smallest SLM in the family is **TranslatePsy-AfriSLM-0.8B**, and its **Q4_K_M** quantization is the lightest practical build while keeping quality (Q4_K_M loses only about 0.005 COMET versus full precision, see Part 2). For very low-end phones there is an even lighter path, **TranslatePsy-AfriNano**, a Bergamot-based 17M to 43M parameter model that supports Swahili in both directions through `en-xx` and `xx-en` packs using the `##SW` tag. AfriNano runs on the Bergamot engine (`modelType:"nmt"`, `engine:"Bergamot"`). Our plan is to demo on **0.8B Q4_K_M** for the best quality-to-size balance, and mention AfriNano as the path for the cheapest phones.

**So what.** Judges running the build themselves get a model that fits and performs. We state the exact model file in the repo and submission. See Parts 2 and 3.

### Q5. What already exists on-device for Swahili translation, and what do we do better?

**Answer. The main alternatives are Google Translate offline packs, Crane AI Labs' Swahili Gemma, and community efforts like Masakhane and Lanfrica.** Google's offline packs need a manual download, fall back to the cloud when online, and send data off the device whenever a connection exists. Crane's Swahili Gemma (from the DeepMind Gemmaverse) is genuinely offline-first and explicitly targets "cost per inference near zero," which validates our whole thesis. Masakhane and Lanfrica are community African NLP efforts, more research than product. **Our edge** is a fully offline, no-account app that combines **voice in, translation, and voice out** across **19 languages** on one local stack (QVAC), with privacy by construction because nothing ever leaves the device. We are not just a model, we are the complete offline loop.

**So what.** We position against Google on privacy and offline purity, and we align with Crane's cost thesis while shipping a broader, voice-enabled, multi-language app. See Part 6.

## Part 2. TranslatePsy-AfriSLM, the translation model

This is the heart of the project. Facts below are from the model card and paper.

### Identity and availability

- **Name.** TranslatePsy-AfriSLM, from Tether AI Research (authors Milan Gritta, Patrik Lambert, Jihye Back, Amril Nazir).
- **Paper.** arXiv:2608.18655, "TranslatePsy-AfriSLM, High-Quality Data Scaling For Low-Resource MT" (EMNLP 2026).
- **Code.** github.com/tether-ai-research/qvac-translatepsy-afri-slm.
- **Weights.** Hugging Face under the `qvac` org, for example `qvac/TranslatePsy-AfriSLM-0.8B-Q4-GGUF` with a file like `TranslatePsy-AfriSLM-0.8B-Q4_K_M-imat.gguf`. A collection page lists all sizes.
- **License.** Model is **Apache 2.0** (permissive, fine for our use). The training dataset is CC-BY-NC 4.0, which does not restrict using the released model weights.

### Sizes and architecture

Three sizes, **0.8B, 2B, 4B**, each a full-parameter supervised fine-tune of **Qwen3.5-{0.8B, 2B, 4B}**. Quantized to **GGUF Q8_0 and Q4_K_M** for on-device use. The family is reported to **outperform TranslateGemma-27B and Qwen3.5-122B-A10B** on African machine-translation benchmarks, which is remarkable for models this small.

### Languages (English plus 19 African languages)

English, Afrikaans (af), Amharic (am), Hausa (ha), Igbo (ig), Kinyarwanda (rw), Lingala (ln), Luganda (lg), Malagasy (mg), Nyanja (ny), Oromo (om), Shona (sn), Somali (so), Sesotho (st), **Swahili (sw)**, Setswana (tn), Wolof (wo), Xhosa (xh), Yoruba (yo), Zulu (zu). All pairs are bidirectional.

### Quality (SSA-COMET on African benchmarks)

| Model | FLORES-200 | BOUQuET | SMOL |
|---|---|---|---|
| AfriSLM-0.8B | 0.5944 | 0.6223 | 0.4973 |
| AfriSLM-4B (best) | 0.6143 | 0.6391 | 0.5136 |

Quantization note. **Q4_K_M loses only about 0.005 COMET versus full precision**, and the GGUF builds are evaluated at a 2048-token context. This is why 0.8B Q4_K_M is our quality-per-megabyte sweet spot.

### Training data and recipe

Trained for one epoch on the **TranslatePsy-AfriSLM-Synthetic-Mix** (215,653,192 bidirectional examples, about 32.37 billion tokens), plus an Instruct Mix and an Asia-Europe Mix, with **NLLB-3.3B as the teacher**. Training ran on 32 H100 GPUs at learning rate 1.25e-5 in bf16.

### Prompt format (important for integration)

The model expects a system and user turn, with language names written out in words.

```
System: You are a professional {src} to {tgt} translator...
User:   Please translate the following {src} text into {tgt}: {text}.

Translation:
```

So for our pair, src and tgt are the words "English" and "Swahili". We must reproduce this template exactly in the app.

### Known limitations (be honest in the submission)

- Trained on synthetic data with no human evaluation reported, so quality varies by language and direction.
- Dialects are underrepresented, so colloquial or Sheng-heavy Swahili may be weaker.
- Not for high-stakes use (medical, legal, financial) without a human in the loop.
- No "thinking" capability. It is a direct translator, not a reasoner.

## Part 3. The QVAC platform, deep dive

QVAC is Tether's local-first AI SDK. These are the integration facts that matter, from the official docs (docs.qvac.tether.io, SDK v0.22).

### Packages and toolchain

- **JavaScript / TypeScript.** `@qvac/sdk`. CLI `@qvac/cli` v0.16.
- **Python.** `tetherto-qvac-sdk`.
- **Toolchain.** Node 22.17 or newer (mobile bundling wants ^22.21.0 or >=24.9.0), npm 10.9 or newer, Bare 1.30.3 or newer, Expo 54 or newer.
- **Docs trick.** Append `.md` to any docs path, or send `Accept: text/markdown`, to get machine-readable docs. A full dump lives at /llms-full.txt.

### Hard platform rules (these constrain the demo)

- **Physical device only, no emulators** (a llamacpp limitation). Run with `npx expo run:ios --device` or `npx expo run:android --device`.
- **Platforms.** macOS 14+ (arm64, Metal), iOS 17+ (Metal, Expo), Ubuntu 22+ (Vulkan 1.4+), Android 12+ (Vulkan, or OpenCL on Adreno 700+, Expo), Windows 10+ (Vulkan 1.4+).
- **Validate the machine** with `qvac doctor` before building.
- **Memory check.** `assessModelFit()` estimates whether a model fits before download (advisory).
- **Downloads are resumable** via `downloadAsset` / `loadModel` with `onProgress`, cancellable by requestId.

### Capability map (what QVAC can do)

Text generation, embeddings, RAG, fine-tuning, multimodal, batch inference, image / video / world / music generation, **transcription**, **text-to-speech**, **voice assistant**, **translation**, BCI, VLA, OCR, image classification, and P2P (blind relays, RPC). For this project we care about three capabilities chained together, **transcription, translation, and text-to-speech**.

### Translation API

- **Default engine** is qvac-fabric-llm.cpp (Bergamot or IndicTrans2 backends).
- **Bergamot engine** (`modelType:"nmt"`, `modelConfig.engine:"Bergamot"`) uses intgemm `*.bin` weights plus `*.spm` vocab, and runs the AfriNano packs.
- **`translate()`** takes `{from, to, text}` and returns translations and text, or a token stream when streaming. Companion functions are `loadModel`, `translate`, `unloadModel`.
- **Language ids** live in `qvac-sdk/schemas/translation-config.ts`.
- **Addons.** `@qvac/translation-nmtcpp` (NMT), `@qvac/llm-llamacpp` (for GGUF LLM-style translation such as AfriSLM).

### Transcription API (voice input)

- **Two engines.** qvac-fabric-speech.cpp (whisper.cpp `.bin`, use `modelType:"whisper"`) and NVIDIA Parakeet (`modelType:"parakeet-transcription"`, GGUF).
- **Whisper** needs a whisper.cpp `*.bin` model and an optional Silero VAD GGML. Upstream whisper.cpp supports Swahili (sw), which is why Whisper is our choice.
- **Parakeet** variants include multilingual TDT (about 750 MB, `PARAKEET_TDT_0_6B_V3_Q8_0`), English CTC / Unified, Sortformer diarization, EOU, and Indic. Heavier than needed for v1.
- **Methods.** `transcribe()` or `transcribeStream()`. macOS and iOS get a Core ML encoder sidecar for speed.
- **Do NOT use** TranscribePsy-250M-EU-sub for Swahili. It is European-only (8 languages).

### Text-to-speech API (voice output)

- **Addon** `@qvac/tts-ggml`, with `modelType:"tts"`.
- **Engines.** Chatterbox (24 kHz), Supertonic (44.1 kHz), Parler (44.1 kHz), CosyVoice3 (24 kHz), Audio8 (44.1 kHz), MOSS (24 kHz), and a LavaSR enhancer (48 kHz). Output is mono 16-bit PCM as a number array.
- **Swahili TTS is NOT confirmed.** The default Supertonic2 voice is English. This is a real gap and shapes the v1 scope (see Part 4).

### Voice-assistant reference

QVAC documents a voice-assistant pattern that chains microphone to Whisper + VAD, to an LLM, to TTS, to speakers. Its defaults are WHISPER_TINY, VAD_SILERO_5_1_2, LLAMA_3_2_1B_INST_Q4_0, and TTS_EN_SUPERTONIC_Q8_0. The example is desktop-only (FFmpeg) but the chaining pattern is exactly ours, with the LLM swapped for AfriSLM translation. Practical tips from the docs are to gate the microphone during TTS playback, and to filter Whisper hallucinations.

### Benchmarks we can cite

TranscribePsy-250M-EU-sub on a phone, RTF 0.052, 1021 ms latency, 252 ms cold start, 534 MiB peak memory, 305 MB size. AfriNano (Bergamot, 17M to 43M), about 3.53x lower peak RAM than NLLB and about 56.7x smaller. These are our on-device reference floors.

## Part 4. Scope decisions forced by the research

Research changed the plan in three honest ways. Record these so `docs/4.solution.md` starts from truth.

1. **Voice input uses Whisper, not QVAC's small model.** QVAC's TranscribePsy-250M is European-only. We use a whisper.cpp tiny or base model for English and Swahili speech, and we test Kenyan-accented English on a real device early.
2. **Voice output is asymmetric in v1.** No Swahili TTS is confirmed in QVAC. So v1 does **speech out in English** and **text out in Swahili**, plus full two-way text. If a Swahili-capable TTS voice is found, we add it as a stretch goal. We state this asymmetry plainly rather than overpromising.
3. **Model choice is 0.8B Q4_K_M for the demo.** Best balance of size and quality, with AfriNano documented as the path for the cheapest phones.

## Part 5. Hardware and measurement plan

- **Target device.** The Apple Silicon Mac (arm64, 16 GB RAM, macOS 27), a fully supported QVAC platform. The builder has no physical phone and QVAC does not run in emulators, so the Mac is the demo device. The Android phone is the documented deployment target for the personas.
- **What we measure.** Cold start, time from end-of-speech to translated text, time from text to spoken audio, and peak memory, all with networking disabled. We record real numbers on the demo Mac.
- **How we de-risk.** Run `qvac doctor`, call `assessModelFit()` for the chosen models, use resumable downloads, and keep the Whisper and translation models as small as the demo allows.
- **What we report.** Device make and model, OS, RAM, the exact model files, and the measured latency and memory, written into the submission for the "working implementation" criterion.

## Part 7. Winning strategy, mapped to the judging criteria

The five published criteria, and exactly how this project answers each.

- **Real user value.** Language access is a daily need for hundreds of millions. Backed by the evidence in `docs/2.problem.md` section 7 (Kenya 48% online, 600M+ Africans offline, Swahili 200M+ speakers and low-resource). Our demo shows a real conversation, not a toy.
- **Meaningful QVAC integration.** Translation (AfriSLM via the translation API) is the core, wrapped by QVAC transcription (Whisper) and QVAC TTS. Three QVAC capabilities chained. Not a wrapper, the whole pipeline is QVAC.
- **Working implementation.** Narrow scope, one clear pipeline, tested on a physical device with measured latency and memory. We ship a repo a judge can run.
- **Usability.** One screen. Speak or type, get speech or text back. Asymmetry (English voice out, Swahili text out) is stated up front so it reads as honest scope, not a bug.
- **Offline-demo clarity.** Airplane mode on camera, a live two-language exchange, unmistakable. This is the single most persuasive asset we can submit.

**Disqualification guard.** No cloud AI API for any core feature. Everything (transcription, translation, TTS) runs on-device. We say this explicitly in the submission.
