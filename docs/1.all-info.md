## 4. The Three Tracks

Choose the track that best matches your project.

### Track 1. Offline AI apps (prize 700 USDt)
Build a useful QVAC app whose **core AI feature works without internet**. Examples include a local assistant, speech tools, search, or translation. **Live translation is a suggested topic.** Choose models and languages supported on your target hardware.

> Highly relevant. QVAC just released **TranslatePsy-AfriSLM**, which translates directly between **19 African languages, offline**.

### Track 2. Cloud to Pocket (prize 900 USDt)
Move an **existing cloud AI workload** onto a device using QVAC. Explain the original (cloud) workflow, what exactly you moved on-device, and the **quality, speed, memory, and privacy tradeoffs**.

### Track 3. On-device agentic finance (prize 400 USDt)
Combine **QVAC local AI with WDK** (Tether's Wallet Development Kit) for a **self-custodial finance workflow**.
- Clearly **distinguish offline AI from transactions and services that require a network**.
- Demonstrate the offline portion **safely with test data and a test environment** (e.g. Sepolia testnet).
- WDK is **required** for this track.

## 8. The Technology Stack (background research)

### 8.1 QVAC, Tether's local AI stack (MANDATORY)

**QVAC** ("Tether's answer to centralized AI") is a free, open-source (Apache 2.0) platform for running AI **entirely on hardware you own**. Phone, laptop, robot, wearable, home appliance. No internet, no cloud, no API keys, no per-token bills, and no data leaving the device.

**Tagline** *"Decentralized, Local AI in a Single API."* Also called the **"Infinite Stable Intelligence Platform."**

**Core properties.** Local-first, offline inference, peer-to-peer model distribution (fetch models from peers, connect across NATs with blind relays), cross-platform (iOS, Android, desktop, Node.js, Bare, Expo), pluggable (include only the capabilities you need), and an **OpenAI-compatible HTTP server** so any tool or harness can use QVAC as a local model provider.

**AI capabilities (one unified SDK, 10+ tasks)**
- Text generation (LLM chat and completion, structured output)
- Text embeddings (semantic search, RAG)
- RAG (out-of-the-box retrieval-augmented generation)
- Fine-tuning (LoRA, even on a phone)
- Multimodal (text and images in one context), Vision
- Image generation, Video generation, World simulation, Image upscaling
- Music generation (ACE-Step and MiniMax-Music3)
- Transcription (Whisper and NVIDIA Parakeet ASR)
- Text-to-Speech, Voice assistant (real-time pipeline), BCI transcription
- Translation (offline NMT via Fabric LLM and Bergamot)
- OCR, Image classification
- Decisions (choice, ordinal-score, and statement-probability questions via **Laya**)
- VLA (vision-language-action for robot control)

**The ecosystem (5 products)**
1. **QVAC SDK**, the single API (JS/TS `@qvac/sdk` on npm, Python `tetherto-qvac-sdk`).
2. **QVAC Genesis**, an open dataset of synthetic STEM reasoning data for training models (free for research and non-commercial use).
3. **QVAC Fabric**, an on-device fine-tuning engine (Vulkan and Metal, desktop and mobile GPUs, dynamic tiling fits tight mobile GPU memory).
4. **QVAC Psy**, QVAC's own open-weight model family, each trained for a single domain and sized for hardware you already own (includes **MedPsy** medical models and the new **TranslatePsy-AfriSLM** for 19 African languages).
5. **QV.AC**, the flagship desktop and mobile assistant app, built with QVAC as a showcase.

**JS/TS SDK quick facts (v0.22, latest at time of writing)**
- Install with `npm install @qvac/sdk`.
- Requirements. Node.js 22.17 or newer (bundling for mobile needs ^22.21.0 or 24.9.0+), npm 10.9 or newer, Bare 1.30.3 or newer (if targeting Bare), Expo 54 or newer (mobile).
- **QVAC currently does NOT run on emulators. You must use a physical device** (llamacpp limitation).
- Minimal flow. `loadModel({ modelSrc: LLAMA_3_2_1B_INST_Q4_0, onProgress })`, then `completion({ modelId, history, stream })`, then iterate `result.tokenStream`, then `unloadModel({ modelId })`.
- Config via `qvac.config.json` (loggerLevel, cacheDirectory, httpDownloadConcurrency, etc.). The `QVAC_CONFIG_PATH` env var points to it.
- For production on Bare use **`@qvac/inference`** (in-process engine). `@qvac/bare-sdk` is deprecated, last release 0.18.2.
- The model "engine" identity (e.g. `llamacpp-completion`, `moss-transcribe`) selects the capability or plugin.

**Built on QVAC (showcase projects)** Hiraia (offline Tagalog and Bisaya science tutor), GENE.01 (Generative Bionics humanoid robot), Diamesh (5-agent ophthalmology copilot on local MedPsy), qvac-finance-agent (local-first crypto trading agent), TaleTrip (bilingual offline storybooks), ResonanceAI (on-device semantic search), Triage-0 (offline clinical triage assistant), Leash (E2E-encrypted local personal assistant).

### 8.2 WDK, the Wallet Development Kit (required for finance track)

**WDK by Tether** is an open-source SDK for building **self-custodial, multi-chain wallets**. The tagline is "Multi-Chain Wallets in Minutes." Users control their keys, and the developer never touches private keys.

- **Chains.** Bitcoin, Ethereum, Solana, TON, TRON, Polygon and more (50+ supported chains, 100K+ wallets created).
- **Modules.** Wallet modules (EVM, UTXO, TON, TRON, Solana, Spark), DeFi modules (Aave, Morpho), Fiat modules (MoonPay), Community modules (RGB, Cosmos).
- **Features.** TypeScript SDK and React Native components, unified API across chains, tree-shakeable modules, Indexer API (balances, transactions, history across chains), MPC support and hardware-wallet integration for enterprise.
- **Quick example.** `WDK.getRandomSeedPhrase()`, then `new WDK(seedPhrase)`, then `wdk.registerWallet('ethereum', { provider: 'https://ethereum-sepolia-rpc.publicnode.com' })`, then `await wdk.getAccount(0)`, then `account.getAddress()`.
- Site https://wdk.tether.io/ (docs, playground, comparison vs other wallet SDKs).

### 8.3 Pears (optional, for device-to-device features)

**Pear** (by Holepunch, "the P2P company") is an installable **peer-to-peer application runtime, development and deployment platform** for zero-infrastructure P2P apps on desktop, mobile, and terminal.

- **Pear SDK.** Data replication, networking, identity, and schemas in one module.
- **Pear Runtime and CLI.** Add the runtime to any app and it becomes updatable and distributable P2P. Ship releases without app stores or servers (`pear touch`, `pear stage`, `pear provision`, then anyone installs via a stable `pear://<app-key>` link).
- **Bare.** The zero-core JavaScript runtime underneath Pear (also used by QVAC's JS SDK).
- Properties. Zero infrastructure cost, NAT and firewall traversal without relay servers, local-first by default, signed releases with optional multisig, OTA updates where peers replicate only changed blocks.
- Sites https://pears.com/ and https://docs.pears.com/

## 10. Strategic Notes for a Winning Build

*(Analysis, not official rules.)*

1. **Offline proof is the whole game.** The demo video must show the core AI feature working with the internet switched off (airplane mode on camera). Pre-download all models before the demo.
2. **Physical device only.** QVAC doesn't run on emulators, so plan testing hardware early.
3. **AfriSLM angle.** Track 1 explicitly suggests live translation, and QVAC just shipped TranslatePsy-AfriSLM (19 African languages, offline). An English to Swahili (or other African language pair) live translator is practically a served theme for a Nairobi hackathon.
4. **Meaningful QVAC use is judged.** Don't just wrap the quickstart. Integrate multiple capabilities (for example transcription plus translation plus TTS, or RAG over local docs) where it adds real user value.
5. **Document tradeoffs for Track 2** (quality, speed, memory, privacy). That's an explicit judging input and easy points.
6. **Declare network dependencies honestly.** A clean offline core plus clearly-listed online extras is better than a hidden cloud call (which disqualifies you).
7. **Repo hygiene counts.** Setup instructions, what was built during the event, disclosure of reused code, model licences, and device, OS, and memory notes are all explicitly requested.
8. **Submit early.** Links must be accessible to judges, so test video and repo access from a logged-out browser.
