# AI Yako. Chosen Solution and Winning Plan

> **Status.** Decision locked. This is the build we take into demo day.
> **Author context.** Solo participant. No physical phone. One Apple Silicon Mac (arm64, 16 GB RAM, macOS 27, Node 26, npm 11). Goal is position 1.
> **Reads with.** `docs/1.all-info.md` (rules), `docs/2.problem.md` (problem), `docs/3.research.md` (evidence).

---

## 1. The decision in one paragraph

We are building **Yako**, a fully offline voice and text translator between English and Swahili, running entirely on the laptop. You speak or type in one language, and it speaks and shows the other, with the machine in airplane mode. It chains three QVAC capabilities into one local agent, **transcription (Whisper) to translation (AfriSLM) to speech (TTS)**. We enter it in **Track 1, Offline AI apps**, and we demo it live on the Mac, offline, on camera. The Android phone build is documented as the deployment target, not the demo device.

---

## 2. Why this wins position 1

Judges score five things. Here is exactly how Yako takes each one, and why it beats a phone app we cannot test.

- **Real user value.** Language access is a daily need for hundreds of millions, and the problem evidence is strong (Kenya 48% online, 600M+ Africans offline, Swahili 200M+ speakers and low-resource). A translator is instantly understood and obviously useful. No judge asks "who is this for."
- **Meaningful QVAC integration.** This is the deciding factor. We are not using one QVAC model. We chain **three** QVAC capabilities (transcription, translation, TTS) into a single agent. That is the deepest possible "meaningful integration" and it is exactly what QVAC's voice-assistant pattern is designed for. Most entrants will demo one model. We demo the platform.
- **Working implementation.** A live, offline, on-laptop demo that a judge can run from the repo beats an untested phone APK every time. We measure real latency and memory on the demo machine and publish the numbers.
- **Usability.** One screen. Press to talk or type, get speech and text back. The scope is tight and the asymmetry (see section 5) is stated up front so it reads as honest design, not a gap.
- **Offline-demo clarity.** We toggle airplane mode on camera, then hold a live two-language exchange. This is the single most persuasive asset in the whole submission and it is impossible to fake.

**Why laptop over phone.** QVAC does not run in emulators, and we have no physical phone. So a phone-first plan would mean shipping something we never ran, which risks the "working implementation" score that decides the win. The Mac is a fully supported QVAC platform (macOS 14+, arm64, Metal). Demoing there is legitimate, testable, and reproducible. We document the phone as the target deployment and keep the code platform-agnostic so the same app runs on Android later.

**Disqualification guard.** No cloud AI API for any core feature. Transcription, translation, and TTS all run on-device. We say this in writing in the submission.

## 3. The product

**Name.** Yako (from "AI Yako", Swahili for "Your AI"). Short, on-theme, and memorable.

**One-line pitch.** Yako is a translator that lives entirely on your device. It hears English and Swahili, translates between them, and speaks back, with the internet switched off.

**Core user flows.**
1. **Speak English, hear Swahili-ready output.** Mic captures English, Whisper transcribes, AfriSLM translates to Swahili, the Swahili text is shown (and spoken if a Swahili voice is available, otherwise read on screen).
2. **Speak Swahili, hear English.** Mic captures Swahili, Whisper transcribes, AfriSLM translates to English, English TTS speaks the result aloud.
3. **Type either language, get text and speech back.** Full two-way text translation, plus English speech out.

---

## 4. Architecture

A single local pipeline, all on-device, no network after model download.

```
                +------------------- Yako (local, offline) -------------------+
                |                                                         |
 microphone --> |  Whisper (transcription) --> AfriSLM (translation)      | --> text out
   or keyboard  |        qvac-fabric-speech.cpp      GGUF Q4_K_M           |
                |                              |                          |
                |                              v                          |
                |                       QVAC TTS (speech out, English)    | --> audio out
                +---------------------------------------------------------+
```

- **Input.** Microphone or keyboard.
- **Transcription.** Whisper tiny or base via `modelType:"whisper"` (supports English and Swahili). Optional Silero VAD for clean end-of-speech. We do NOT use TranscribePsy-250M-EU-sub (European-only).
- **Translation.** `TranslatePsy-AfriSLM-0.8B` in **GGUF Q4_K_M**, run through the QVAC translation / LLM addon, using the exact prompt template from the model card (system "professional {src} to {tgt} translator", user "Please translate...").
- **Speech out.** `@qvac/tts-ggml` (`modelType:"tts"`) for English output. Swahili output is text-first in v1 (see section 5).
- **Shell.** A small desktop app (Expo or a thin local web UI over the QVAC JS SDK) with one screen and a big talk button.

**Why the 0.8B model.** Best quality-per-megabyte (Q4_K_M loses only about 0.005 COMET versus full precision) and it fits comfortably in 16 GB RAM alongside Whisper and the UI. We run `assessModelFit()` first and document AfriNano (Bergamot) as the path for very low-end phones.

## 5. Honest scope decisions (from research)

These are deliberate, evidence-based calls. We state them in the submission so they read as design, not omissions.

1. **Voice input uses Whisper, not QVAC's small model.** QVAC's TranscribePsy-250M is European-only. Whisper covers English and Swahili.
2. **Speech output is English-only in v1.** No Swahili TTS is confirmed in QVAC. So Swahili output is shown as text, and English output is spoken. If a Swahili voice is found, it is a stretch goal.
3. **Demo is on the Mac.** Physical-device rule plus no phone. The Android path is documented for deployment.
4. **Demo language is clear, standard Swahili.** AfriSLM is weaker on dialect and Sheng, so the live demo uses clean phrases and we note the limitation honestly.

## 6. Build plan (about 3 days)

Ordered so the riskiest, most convincing parts land first.

- **Day 1, foundation.** `qvac doctor` on the Mac. Scaffold the app shell and QVAC SDK. Download AfriSLM-0.8B-Q4_K_M and a Whisper tiny model with resumable downloads. Get **typed English to Swahili text** working end to end in airplane mode. This alone proves the core.
- **Day 2, the voice loop.** Add Whisper transcription (mic in, both languages) and English TTS out. Gate the mic during playback and filter Whisper hallucinations (per QVAC voice-assistant guidance). Test Kenyan-accented English on the real mic. Measure cold start, speech-to-text latency, and peak memory.
- **Day 3, polish and proof.** One-screen UI cleanup. Record the airplane-mode demo video. Write the README, the offline-evidence section, the device and model details, and the network-feature list. Upload early and test every link.

**Cut line if time bites.** Drop Swahili TTS stretch goal and any extra languages first. Protect the core English-Swahili voice loop and the offline video at all costs.

## 7. The demo (how we actually win the room)

A 60 to 90 second video plus a live run.

1. Show the Mac, wifi and data on, app open.
2. **Turn on airplane mode on camera.** Say it out loud. "No internet. Everything you see next runs on this machine."
3. Speak English. "Where is the nearest clinic?" Watch Swahili text appear. (And hear it if Swahili voice lands.)
4. Speak Swahili. "Ninataka kwenda sokoni." Hear English spoken back. "I want to go to the market."
5. Show a typed exchange both directions.
6. Close with the on-screen facts. Models, sizes, measured latency, "100% on-device, no account, no API key, no cost per use."

That airplane-mode moment, with a real conversation, is what separates position 1 from everyone demoing a single model.

## 9. Risks to the win, and counters

| Risk | Counter |
|---|---|
| Whisper misses Kenyan-accented English | Test on the real mic day 2, keep typed input as a first-class path, tune VAD |
| No Swahili TTS | Ship English voice out and Swahili text out, state it as honest scope, stretch goal if a voice appears |
| Model slow on 16 GB | 0.8B Q4_K_M, `assessModelFit()`, measure and publish real numbers, close other apps during demo |
| Judges expect a phone | Lead with the offline laptop demo (fully supported), document Android as the deployment target |
| Scope creep kills the deadline | Lock the single pipeline, cut stretch goals first, protect the offline video |
| Broken link at submission | Upload early, verify every link in a private window |

## 10. What "done" looks like

A judge clones the repo, runs one setup command, downloads two models, turns off their wifi, and holds a spoken English-Swahili exchange on their own machine. The video shows the same thing live. The README explains the three QVAC capabilities chained together and why that matters for 600 million offline people. That is a position 1 submission.
